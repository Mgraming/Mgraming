# تشغيل السيرفر على Supabase — خطوة بخطوة

Supabase بيدّينا في مكان واحد: قاعدة بيانات، وتسجيل دخول، ورسايل لحظية للشات، وتخزين صور. ملف `schema.sql` فيه قاعدة البيانات كاملة بالصلاحيات، ومتجرّب (`npm run test:db`).

> **ملاحظة:** شاشات Supabase بتتغيّر كل فترة. لو اسم زرار مختلف شوية عن المكتوب هنا، دوّر على أقرب اسم ليه. ولو حاجة مش واضحة، ابعت صورة الشاشة.

## قبل ما تبدأ
- حساب GitHub أو إيميل.
- ١٥ دقيقة تقريباً.
- **التكلفة:** الباقة المجانية كفاية للتجربة. متدخلش بيانات فيزا في الخطوات دي. لو الموقع طلب منك تدفع أو تعمل Upgrade، وقّف وقولي.

---

## الخطوة ١: عمل الحساب
1. افتح **supabase.com** ودوس **Start your project** (أو **Sign in**).
2. اختار **Continue with GitHub** (الأسهل) أو سجّل بإيميل.
3. لو سألك على **Organization**: اكتب اسم زي `Passport` واختار الباقة **Free**.

## الخطوة ٢: عمل المشروع
1. دوس **New project**.
2. املا:
   - **Project name:** `car-passport`
   - **Database Password:** دوس **Generate a password**، وبعدين **انسخه واحفظه في مكان آمن عندك** (Notes على الموبايل أو مدير باسوردات). **متبعتهوش لحد ولا ليا.**
   - **Region:** اختار الأقرب لمصر — **Frankfurt (eu-central-1)** أو أي منطقة في أوروبا.
   - لو ظهر لك اختيارات زي **Enable Data API** أو **Enable automatic RLS**: سيبهم شغّالين (الوضع الافتراضي).
3. دوس **Create new project** واستنى دقيقتين لحد ما المشروع يجهز.

## الخطوة ٣: تشغيل قاعدة البيانات
1. من الشريط اللي على الشمال، افتح **SQL Editor** (أيقونة شبه `>_`).
2. دوس **New query** (أو علامة **+**).
3. افتح ملف `supabase/schema.sql` من المشروع على GitHub، دوس **Raw**، واختار الكل وانسخه (`Ctrl+A` ثم `Ctrl+C`).
4. الصقه في SQL Editor ودوس **Run** (أو `Ctrl+Enter`).
5. لو ظهر تحذير زي **"potential issue"** أو **destructive operation**: ده طبيعي لأن الملف بيعمل صلاحيات — دوس **Run this query** / **Confirm**.
6. المفروض تشوف **Success. No rows returned**.

> **لو ظهر Error:** متعدّلش في الملف. صوّر رسالة الخطأ وابعتهالي. ومتشغّلش الملف مرتين على نفس المشروع.

## الخطوة ٤: التأكد إن كل حاجة اتعملت
1. **New query** جديدة.
2. انسخ محتوى `supabase/check.sql` والصقه ودوس **Run**.
3. هيطلع جدول فيه ٦ سطور. **كلهم لازم يكونوا ✅**. لو في ❌، ابعتلي صورة الجدول.
4. اختياري: افتح **Table Editor** هتلاقي ١٥ جدول (cars، workshops، products، …) وجنب كل واحد علامة إن RLS شغّال.

## الخطوة ٥: تسجيل الدخول
1. من الشمال: **Authentication** ← **Sign In / Providers** (أو **Providers**).
2. **Email** بيكون شغّال من الأول — سيبه. ده اللي هنبدأ بيه لأنه **مجاني**.
3. **Phone** (الدخول برقم الموبايل) **متفعّلهوش دلوقتي**: محتاج حساب عند شركة رسايل SMS زي Twilio، والرسايل بتتدفع. نقرر فيه بعدين.
4. من **Authentication** ← **URL Configuration**: في **Site URL** اكتب مؤقتاً `http://localhost:8080` — هنغيّره للرابط الحقيقي لما ننشر التطبيق.

## الخطوة ٦: الحاجتين اللي هتبعتهم لي
1. **Project URL:** دوس زرار **Connect** فوق في نص الصفحة (أو **Project Settings** ← **Data API**)، وانسخ الرابط اللي شكله:
   `https://xxxxxxxxxxxx.supabase.co`
2. **Publishable key:** **Project Settings** (الترس تحت على الشمال) ← **API Keys**، وانسخ المفتاح اللي بيبدأ بـ:
   `sb_publishable_...`
   - لو لقيت زرار **Create new API keys**، دوس عليه الأول وبعدين انسخ الـ publishable.
   - لو مش لاقي غير المفاتيح القديمة (Legacy)، ابعت **anon public** بدله.

**ابعتلي الاتنين دول بس.**

## ⚠️ الحاجات اللي **متتبعتش** أبداً
| الحاجة | ليه |
|---|---|
| **Database Password** | بيفتح قاعدة البيانات كلها |
| **Secret key** (`sb_secret_...`) | بيعدّي كل الحماية |
| **service_role** (القديم) | نفس الـ secret |

الـ **publishable key** عادي يبقى في التطبيق وعلى GitHub، لأن الحماية كلها في قواعد RLS اللي في قاعدة البيانات.

## الخطوة ٦½: تحديث ٠٠٢ (البنزين والورق والصور)
لو كنت شغّلت `schema.sql` قبل التحديث ده: **SQL Editor** ← **New query** ← الصق `supabase/migrations/002_garage_sync.sql` ← **Run**. وبعدين شغّل `check.sql` تاني — لازم ٧ سطور كلهم ✅.
(لو لسه هتشغّل `schema.sql` لأول مرة، التحديث ده جوه الملف ومش محتاج تشغّله لوحده.)

## تحديث ٠٠٣ (مصدر التسجيل)
**SQL Editor** ← **New query** ← الصق `supabase/migrations/003_attribution.sql` ← **Run**. ده بيخليك تشوف كل ورشة سجّلت من أنهي لينك (زيارة، واتساب، فيسبوك…). التطبيق شغال عادي حتى لو لسه ما شغّلتهوش.

## الخطوة ٧ (بعد ما تعمل حساب في التطبيق): خلّي نفسك أدمن
ده هيبقى بعد ما أربط التطبيق، عشان تقدر توافق على الورش والمحلات:
1. سجّل في التطبيق بإيميلك.
2. **Table Editor** ← **profiles** ← هتلاقي سطر بإيميلك/رقمك.
3. غيّر خانة **role** من `owner` لـ `admin` واحفظ.

## اللي جوه قاعدة البيانات (للمرجع)
| الجزء | الجداول |
|---|---|
| الناس | `profiles` (صاحب عربية / ورشة / محل / أدمن) |
| العربيات | `cars`، `service_records` |
| الورش | `workshops`، `workshop_services`، `jobs`، `warranties`، `warranty_claims`، `reviews` |
| الشات | `conversations`، `messages` |
| قطع الغيار | `parts_stores`، `products`، `orders`، `order_items` |

### قواعد بتفرضها قاعدة البيانات نفسها
- كل واحد بيشوف عربياته بس، ورقم الموبايل مش بيظهر لحد.
- الورشة أو المحل بيتسجّل «في انتظار المراجعة»، والأدمن بس اللي يوافق.
- الشات بيشوفه طرفينه بس.
- الضمان بيبدأ لوحده لما الورشة وصاحب العربية الاتنين يأكدوا الشغلانة.
- التقييم بس لصاحب العربية على شغلانة اتأكدت — تقييم واحد لكل شغلانة.
- سعر الطلب وإجماليه بيتحسبوا على السيرفر، والمخزون بينقص لما المحل يأكد ويرجع لو اتلغى.

## بعد ما تبعت الـ URL والـ key
أنا هربط التطبيق: تسجيل الدخول، مزامنة العربيات والسجل، الورش والمحلات الحقيقية، الشات اللحظي، الطلبات، صور الفواتير، ونقل البيانات اللي على الموبايل لحسابك أول مرة تسجّل دخول.
